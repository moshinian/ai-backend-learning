# 多轮 RAG 中把会话历史等同于检索 Query

## 1. 错误表现

1. 面对“荣耀 13 手机多少钱 -> 这个手机什么时候发布”的追问，先回答携带历史消息、关联会话 ID、使用 Agent 或 MCP，没有直接说明最终送入检索器的 Query。
2. 一度考虑把历史上下文直接塞进 Prompt，却没有区分生成 Prompt 和向量 / 关键词检索输入。
3. 经面试官提示后才收敛到 Query rewrite，并把它描述成模糊的“Query 优化”。

## 2. 根因

1. 当前 RAG 主线以单轮问题为输入，个人项目代码尚未实现多轮独立 Query 改写。
2. 把“模型生成答案需要会话历史”和“检索器需要语义完整的搜索 Query”当成同一个问题。
3. 听到指代词后过早联想到 Agent、MCP 和会话存储，没有先定义信息缺口：当前问题中的“这个手机”缺少实体。

## 3. 正确理解

1. 多轮检索先读取必要的会话历史，把当前追问改写成可以脱离上下文独立理解的 Query，例如：

```text
历史：荣耀 13 手机的价格是多少？
当前：这个手机什么时候发布？
独立 Query：荣耀 13 手机什么时候发布？
```

2. 独立 Query 用于关键词检索、向量检索或两者；原始历史、独立 Query 和召回证据再按 Token 预算进入最终回答 Prompt。
3. Query rewrite 不等于把全部历史拼到 Query。要保留实体、时间、否定和约束，去掉无关对话；存在多个候选实体时应澄清，而不是擅自选择。
4. 需要记录原始问题、使用的历史范围、改写 Query、模型 / Prompt 版本和召回结果，评估指代消解准确率、Recall@K、延迟和成本。
5. 当前个人项目代码未发现独立 Query rewrite 实现；在代码验证完成前，只能把它表述为明确缺口或后续方案。

## 4. 复盘触发条件

1. 用户问题包含“它、这个、刚才那个、第二种方案”等指代词。
2. 面试官追问“最终送给 Embedding 模型的文本是什么”。
3. 准备回答“把历史消息全部带上”或“使用 Agent / MCP”时。
4. 多轮问答召回失败，但单独补全实体后能够召回正确证据时。
