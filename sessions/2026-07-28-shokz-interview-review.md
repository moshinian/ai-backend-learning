# 2026-07-28 韶音科技面试复盘与知识边界整理

## 日期

2026-07-28

## 主题

还原韶音科技高级 Java 工程师（供应链）真实面试，纠正会议助手转述偏差，归纳数据幂等、MySQL 表空间、RAG 回答质量和 Spring Bean 生命周期四个追问。

## 本次做了什么

1. 排除此前误贴的其他场次纪要，只以候选人逐题还原和本场正确会议摘要作为证据。
2. 复盘 ERP 数据集成幂等，区分单批次单执行者、数据库原子条件、业务唯一键和重复执行幂等。
3. 复盘冷热分离，区分 InnoDB 页可复用、物理表空间缩小、操作系统磁盘回收和云平台存储指标。
4. 复盘 RAG 回答质量，区分链路追踪、检索召回、融合 / 排序、生成忠实性和评测；确认 Rerank 在独立分支 Demo 中做过尝试，但未进入正式主链路。
5. 校准 Spring Bean 回答：现场核心作用域边界基本正确，仍需用“创建、注入、增强、销毁”补齐生命周期主线。
6. 将面试后的强烈挫败感还原为学习方法问题：不追求穷举背诵，改用少量关键词入口、真实证据和知识边界表达。

## 关键结论

1. “业务不会并发”可以是现网前提，但不能替代对“先查再写不原子”的机制回答；应先承认风险，再说明单执行者约束和数据库兜底。
2. 能确认生产现象不等于掌握底层机制。回答应明确区分已确认事实、合理推断和当前未知。
3. RAG 的 `trace_id`、`session_id` 保障追踪与关联，不保障答案相关性；质量回答应按召回、排序、生成和评测分层。
4. Rerank 的准确事实是“独立分支 Demo 已尝试，正式主链路未落地”，既不能说完全没做，也不能包装成生产能力。
5. Spring Bean 现场回答没有原则性错误，主要是没有展开完整生命周期；四词入口比孤立背诵回调接口更适合恢复。
6. 面试官追问到未知处是能力探测的常见终点。长期目标是稳定说明边界，而不是记住所有可能被问到的细节。
